# Brief 6.16: Rust tests of the commands through Tauri's own mock runtime

Read CLAUDE.md first (Safety before all), then docs/DESKTOP_GAPS.md ("Unproven", and "The cheapest cover", item 4).
Kevin approved item 4 on Nov 14: **tauri's own `test` feature, no new crate.**

## Why

Each command's inner function has Rust unit tests, and the page's side is tested with `invoke` mocked. Nothing
calls a command the way the page does: by its registered name, with arguments as JSON, through the permissions,
getting the answer as JSON. 6.14's contract test compares names and argument keys as text; this runs them.

## The one dependency change

In src-tauri/Cargo.toml, switch on tauri's `test` feature **for tests only**: a `[dev-dependencies]` entry
`tauri = { version = "2", features = ["test"] }` (same version requirement as the main entry, so Cargo.lock gains
no new crate version; check `git diff src-tauri/Cargo.lock` and report exactly what changed in it: if any crate is
added that wasn't in the lock before, stop and report before going on). Release builds must not get the feature.

## What to build

1. **A test harness** in src-tauri (a `#[cfg(test)]` module, suggest src-tauri/src/command_tests.rs plus small
   helpers): builds the app with `tauri::test::mock_builder()` using the **same** `invoke_handler` list and managed
   state as the real app, so a command missing from the real list is missing here too. That needs lib.rs's builder
   set-up split so the handler list and state are made by one function both `run()` and the tests call: do that
   split with no change in behaviour. Then `tauri::test::get_ipc_response` (or the current equivalent in the tauri
   version in Cargo.lock: read its docs in ~/.cargo/registry source, don't guess) sends an `InvokeRequest` with the
   command's name and a JSON body and returns the JSON answer or error.
2. **Tests, one group per feature of the audit's "Unproven" table, for every command that needs no native dialog
   and no network:** call it by name with the argument JSON **exactly as the page sends it** (read the page's call
   in src to copy the keys and shapes; 6.14's contract test lists them), and assert on the JSON that comes back, in
   the shape the page reads. Priority order; do as many as fit, and list in the report which commands are covered
   and which are not, with the reason:
   - the project file: create, open, an edit (exec/query), a blob write and read, the refusals of B3, copy, close;
   - backups, the lock file, the recent list / app data;
   - exports: choose-token paths can't be driven without a dialog, so test `export_write` and the commit against a
     token made through whatever test seam exists; if none exists without changing release code, skip and say so;
   - week start, time zone at a place, fonts list, licence text, the service list;
   - opened-files (`opened_files_take`);
   - commands that go to the network (weather, tiles, address, hospital) only where the code already has a fixture
     seam; never contact a real service.
   - Dialog commands (`*_choose`) are out: they can't be driven.
3. **Permissions:** the mock runtime checks capabilities if the app is built with the real `tauri.conf.json`
   context. Use `tauri::generate_context!()` (the real config) if it works under test, so the capability files are
   exercised; if the mock needs `tauri::test::mock_context`, say so in the report: then permissions stay untested.
4. Temp files only in a `tempfile`-style folder the existing Rust tests already use (look at how sbd.rs's tests
   make theirs): no new crate.

## What not to touch

Existing tests and assertions; the commands' behaviour; .github; .claude; tauri.conf.json; the page. No crate
beyond the feature flag.

## Checks (foreground, one at a time; cargo's first build here is long: give each the full 10 minutes and run it
again if it times out)

- `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings`
- `cargo test --manifest-path src-tauri/Cargo.toml --lib` (counts; if ffmpeg-dependent tests fail only for lack of
  the sidecars in src-tauri/binaries, name them and go on)

  --manifest-path src-tauri/Cargo.toml -e features -i tauri --edges normal` that the normal (non-dev) dependency
  doesn't have `test`.
- `npx vitest run` (the contract test reads lib.rs: the split must not break it).
