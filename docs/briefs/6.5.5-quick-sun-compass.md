## What to build

1. **The schema version of 6.5.** One new version (the next number), made here, for every new prop of "6.5 canvas
   polish". A migration file as the others are (backup first is the framework's rule), doing only what is
   needed. docs/SBD_FORMAT.md gets a section for the version listing every new prop: this brief's (below), and a
   list headed "Added to this version by later 6.5 milestones" that the next briefs fill in. **Check now whether a
   NEW RECORD TYPE needs anything in the database or in a list of allowed types** (a CHECK constraint, a type
   table, a validator in projectJson.ts, the JSON/CSV round trip): 6.5.8 will add a `settings_preset` record
   under the project (props: `name`, `settings`). If a new type needs a structural change, make it in this
   version's migration now and say so; if it needs only a line in a TypeScript list, add that line now too
   (the type with no UI), with a round-trip test. Additive only: nothing existing is changed or removed.
2. **Coordinates as text**, one pure function in src/core/model (e.g. `coordinates.ts`): parses what a person
   types or pastes: `40.8677, -73.9212`; with or without the space; a space instead of the comma; `40.8677° N,
   73.9212° W` and `N 40.8677 W 73.9212`; degrees-minutes-seconds as Google Maps shows them
   (`40°52'03.7"N 73°55'16.3"W`). Latitude −90..90, longitude −180..180; anything else is refused with a reason
   the UI can say. A decimal comma is not accepted (it is ambiguous with the separator); say so in the help.
   Formats back as `40.8677, -73.9212` (4 decimals shown; full precision kept in the file as locations keep it).
3. **Quick sun.** The sun path item gains optional props (names to match the file's style; proposed
   `own_latitude`, `own_longitude`, `own_date` as `YYYY-MM-DD`): typed or pasted in the sun's settings (the
   Selection tile, where the sun path's settings are today). The reading rule, ONE function in src/core/model
   beside sunPath.ts that the tile, the drawing, the compass, the legend and later the MCP all use:
   - place: the frames' location's coordinates when the setup has one with coordinates, else the item's own;
   - date: the frames' shoot day when there is one, else the item's own;
   - zone: the location's `time_zone` where the place is the location's, else found from the coordinates offline
     (the tzf-rs command; in the dev build, whatever stands in for it today);
   - each of place and date independently says its source: "From the location: [name]", "From the shoot day:
     [date]", or "Its own". The settings show both sources at all times; own fields stay editable but are marked
     "not used while the setup has a location / a shoot day".
   - With neither source for place or date, it says what's missing and draws nothing, as today.
   Everything through ops. What the existing rule does for several frames with different locations or days stays
   exactly as it is; the own values are only the fallback when that rule yields none.
4. **A location's place by pasted coordinates.** In the Locations tile, beside Search address: a field (or the
   coordinates field itself if one exists) that takes pasted coordinates (the parser above) and sets the
   location's latitude and longitude in one op, moves the map's pin, and finds the time zone offline exactly as a
   moved pin does today (`map_moved` or the same path). No request to Nominatim, ever, from this field: assert it.
   The address stays as typed.
5. **The compass.** At the plan's top-right corner, on screen only (app chrome over the canvas, like the tool
   strip; it follows the app's theme; it is not an item, never printed: the print keeps its own north). It shows
   north as the room has it (turning with the room's north), and the sun for the plan's date from the reading
   rule: the arc from sunrise to sunset around the rim and the sun's direction at the time the sun path item
   shows (if the sun path has no time of its own, at solar noon; say which). With no north set: an "N?" state;
   with no place or date: north only. It is a button: its accessible name says "North is [bearing]. Sun: [state]",
   and it opens the settings of north and the sun (select the room's north / the sun path item so the Selection
   tile shows them, or a small popover with the same fields; whichever reuses the existing editors). If the room
   has no sun path item, opening offers "Add sun path" (the action that exists today). It never overlaps the
   zoom control or the Paper/Dark toggle; say where each sits.
6. **For the MCP and 3D later:** the reading rule's result type (place, date, zone, each with its source, and the
   day's sun positions) is exported from src/core/model and documented in a comment as what `get_plan` will
   return. No MCP code.
