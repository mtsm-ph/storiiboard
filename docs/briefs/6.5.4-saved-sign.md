## Kevin's words

"Saving: the app already saves every change at once and backs up every 5 minutes; keep that, no timer. Add a
small 'Saved' sign with the time of the last change and of the last backup."

## What to build

1. **The sign**, in the status bar (24 px, design/DESIGN.md: 10 px uppercase mono labels, times in JetBrains
   Mono), shown while a project is open: `Saved 14:32 · Backup 14:30`.
   - "Saved HH:mm": the time the last op group was committed to the file in this session (the store knows when a
     commit returned). Before any change this session: the newest op's timestamp from the project's History if
     that is cheap to read (one query at open; say what you used), else just "Saved".
   - While a commit is in flight (rare, milliseconds) it may say "Saving…", but only if the store already has
     that state; add no timer and no polling. If a save fails, today's error handling stays as it is and the sign
     must not say "Saved" for the failed change: it shows "Not saved" in the warning colour with the existing
     error path's words; say what the app does today on a failed commit and what the sign does then.
   - "Backup HH:mm": the time of the newest backup of this project; "No backup yet" when there is none. It
     updates when a backup is written (the app already knows when it writes one; no new timer, no new polling of
     the disk; if the only way to learn of a backup is a list call, call it once at open and after each backup the
     app itself triggers).
   - Times in this computer's locale and time zone, 24 h or 12 h as the app formats times elsewhere. A time from
     another day shows its date too (short).
   - Its accessible text reads whole: "Saved at 14:32. Last backup at 14:30." A tooltip on hover and focus says
     the same plus "Every change is saved at once; a backup is made every 5 minutes when the project has
     changed." Clicking it opens Settings → Backups (it is a button; keyboard reachable).
   - en and es through t()/tn() ("Guardado 14:32 · Copia 14:30"; use the words the Backups settings already use
     for a backup in Spanish).
2. Nothing about saving or backups changes: no Save button, no timer, no new write. The sign never writes to the
   project and marking nothing changed. Layout changes, the canvas Paper/Dark toggle and settings are not project
   changes and do not move the Saved time.

   set only when the commit of an edit itself threw (apply, applyWith, undo, redo, restore: the write, not what

2. An edit that wrote nothing doesn't move the time: `touched !== null && touched.size > 0`. Test with an empty

   say "Saved": it says "Not saved" with the words that state already shows. Test.
4. The backup's time: say in a comment that the time read at open comes from the backup's name (local time when
   it was made), so after travel across time zones it can be off until the next backup; no Rust change.

6. Words: a time from another day has its own keys, en "Saved on {day} at {time}." and es "Guardado el {day} a
