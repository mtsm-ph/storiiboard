# Brief 5.6a: a deck as a PDF, and its pages as PNGs

For the builder (.claude/agents/builder.md). Written by the main session, Nov 11, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

The first half of milestone 5.6 (docs/PLAN.md, "Phase 5 milestones"; Kevin's answers in docs/PHASE5_DECISIONS.md,
decisions 3, 4 and 7): export a deck (5.5) as one PDF, a page per page frame in the deck's order, and each page as a
PNG. Builds on 5.0 to 5.5: read docs/briefs/5.0-canvas-core.md through 5.5-decks.md, then src/ui/canvas/ and
src/features/moodboards/. Read src/features/export/ first: the registry, the storyboard PDF (pdfStoryboard.ts), the
PNG frames (pngFrames.ts), names.ts, watermark.ts and the export dialog; follow their patterns, and the files go to
disk through src/core/storage as they do (CLAUDE.md, Export). 5.6b does palettes and swatches.

## Decisions that apply

- **Where:** an Export button on a deck (beside Present) opens the app's export dialog with two formats: "Deck as
  PDF" and "Pages as PNG". They're registry entries like the others (a format is one file plus one line), scoped to
  the open deck. The file names follow the app's language ("Pitch deck.pdf", "Pitch deck 01 Title.png", numbered in
  page order; names.ts's rules for safe names); a PNG export writes into a folder the person picks.
- **What prints:** exactly what Present shows (5.5's presentPages and PageStage): the pages in order, each with the
  items wholly inside it, live cards as they are now, no editing hints, nothing outside pages. The project's watermark
  applies as it does to the storyboard PDF (watermark.ts).
- **PDF pages** (pdf-lib, already in the build): 16:9 at 960 × 540 pt, 9:16 at 540 × 960, 4:5 at 540 × 675, A4 at
  595.28 × 841.89 and Letter at 612 × 792 (landscape swapped); the page's world units scale to that size. The page's
  background fills it. Title metadata is the deck's name; no author, nothing personal.
- **Vector, not a screenshot:** shapes, stickies, sections (with their names; a page's own number and name never print), connectors (with arrowheads) and the
  cards' frames draw as PDF paths; text as real text in its font (selectable, searchable); rotation through a
  transformation matrix around the item's centre, as the canvas does. Text is laid out with the same line breaks the
  canvas uses (5.1a's measurer and wrapping), so lines break where they do on screen; then each line is placed with
  the PDF font's metrics. Link cards are clickable link annotations (http and https only, through the same check as
  the opener).
- **Fonts** (decision 7, Kevin Nov 10: never embed a font whose licence bits forbid it): every font is embedded with
  @pdf-lib/fontkit (already in the build), subset, except:
  - `fsType` (5.1a reads it for system fonts; bundled fonts are all OFL and embeddable) with the restricted bit
    (0x0002) and neither preview-and-print (0x0004) nor editable (0x0008): not embedded; the text uses Inter Tight.
  - bitmap-only (0x0200): not embedded; Inter Tight.
  - no-subsetting (0x0100): embedded whole, not subset.
  - A font this computer lacks (5.1a's missing fonts): Inter Tight.
  - After the export, one notice lists each font that wasn't used and why ("Brand Sans: its licence doesn't allow
    embedding, so Inter Tight was used"), en and es. The export still finishes.
- **Pictures at full quality** (decision 4, Kevin Nov 10: the pointer to the original is for full-quality export):
  - The PDF uses each picture's original file when it's there (media `source_path`, resolved against the .sbd, as the
    frames' pipeline resolves it): read through Rust (a new read-only command in src-tauri that takes the project and
    the picture's SHA-256, reads the path the project stores for it, refuses anything not an image, files over
    200 MB and paths that climb out of the project's folder when relative; never a path from the page), decoded in
    the webview and redrawn into an sRGB canvas (as 4.12 redraws the company logo: P3 photos would print with the wrong
    colours otherwise), at most 6000 px on the long edge and never more than the picture's printed size needs at
    300 dpi, then JPEG at 0.92 (PNG when it has transparency). Video posters and frame pictures in shot cards are
    treated the same way.
  - When the original is missing, unreadable or a pasted picture: the stored 2560 px picture, redrawn the same way;
    the notice after the export says how many used the stored copy ("3 pictures printed from their stored copy:
    their original files weren't found").
  - Crops (shot cards show a frame's crop) apply as on screen.
- **PNGs** render each page with the canvas's own renderer (PageStage, read-only, as Present draws it) at 1× or 2×
  (a choice in the dialog; 1× is the page's world size, so a 16:9 page is 1920 × 1080), from the stored pictures (2560
  px is enough for 2×); sRGB.
- **Progress:** pages are done one at a time, with the dialog's progress and Cancel (no file is left behind on
  Cancel or failure: write to a temporary name and rename, as the storyboard export does, if it does).
- Empty pages export as their background. A deck with no pages: the formats are disabled with a reason.
- Every word through t()/tn(), en and es; the PDF's own words (none beyond the watermark) follow the app's language.

## Files

- src/features/export/ (two registry entries: deckPdf.ts, deckPng.ts, and their tests), src/features/moodboards/

  with tests, registered in lib.rs), src/core/i18n/locales/en.ts and es.ts.

## Tests to add

- Rust: the original-picture command reads a stored path relative to the project, refuses a path climbing out, a
  non-image, an oversized file, and a SHA the project doesn't have.
- Vitest: PDF page sizes per format and orientation; page order; items outside pages absent; text is real text (the
  PDF's content stream has the words, the font is embedded and subset); a restricted fsType falls back to Inter Tight
  and is reported, no-subsetting embeds whole, bitmap-only falls back; rotation matrix; a link annotation for a link
  card, none for javascript:; a P3 picture is redrawn in sRGB (the embedded image has no P3 profile and its pixels are
  converted), the long-edge cap; the stored-copy fallback and its count; PNG sizes at 1× and 2×; file names in en and
  es; Cancel leaves no file.
- Playwright (Chromium, `?files=memory`): export a Pitch deck from the template as PDF and read it back (page count,
  page sizes, the deck's title words present, the "Dates to come"-style text, no text from an item outside pages);
  export PNGs and check their count and size; a deck with no pages has the formats disabled; axe on the dialog, light
  and dark. No console errors.
