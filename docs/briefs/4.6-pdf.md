# Brief 4.6: the call sheet as a PDF

For the builder (.claude/agents/builder.md). Written by the main session, Nov 10, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

A day's call sheet exports as a PDF to send to cast and crew: Letter or A4, in the app's look, every word translated,
with each location's address, coordinates, a directions link and a QR code (docs/PHASE4_DECISIONS.md, decisions 4 and
8; CLAUDE.md, "Call sheets" and "The map on paper"). The map image comes later (4.10); version and issue time (4.7).

Builds on the Call sheet tile (4.1 to 4.5): src/core/model/callsheet.ts (`callSheet(...)` gives every section's data),
src/features/callsheets/ (the sections; the forecast in forecast.ts/useForecast.ts; the sun in
src/core/model/sunTimes.ts; the hospital and emergency number from 4.5). Read docs/briefs/4.1-call-sheet.md to
4.5-hospital.md first. The storyboard PDF (src/features/export/pdfStoryboard.ts, pdfStoryboardFormat.ts) shows how the
app draws PDFs with pdf-lib and its bundled fonts (src/features/export/fonts: Inter Tight and JetBrains Mono, never a
CDN), wraps text, names files (names.ts) and writes through src/core/storage (exportFiles.ts `chooseExportFile`).

## Decisions that apply

- **Where:** an "Export PDF…" button in the Call sheet tile's top row, beside the day picker, with a Paper choice
  next to it (Letter / A4). It writes one file through `chooseExportFile` (the Save dialog on the desktop; the browser
  build's own route in tests, as the storyboard export does: read how e2e/export.spec.ts checks a PDF's text).
  - File name: "<project title> — Call sheet — Day 3 — 2026-11-16.pdf" in the app's language (words through `t()`,
    the date as YYYY-MM-DD so it sorts), made safe with `safeName`.
  - Paper: by this computer's region (Letter for US, CA, MX, PR and the other Letter countries: CLDR's
    `measurementSystem`/paper preference isn't in Intl, so a small list in code: US, CA, MX, PH, CL, CO, VE, PR, GT,
    SV, NI, CR, PA, DO, BO; everything else A4), using the same region source as 3.17's week start and 4.4's units
    (src/app/weekStart.ts, src/app/weatherUnits.ts); the choice in the tile overrides it and is kept in this
    computer's settings (src/core/storage/settings.ts), never in a project. Say in the code where the list came from.
- **What it prints** (the same data the tile shows, never fetched again for the PDF: the forecast is whatever the sheet
  holds, cached or not; no forecast prints "Forecast not fetched"):
  1. Header: project title (and the company's name and logo if the project has a company profile attached: read
     src/core/model/company.ts and how the storyboard PDF prints them, if it does; otherwise title only), "CALL SHEET",
     "Day 3 of 5", the full date, crew call large, wrap. Leave a clear spot top right for 4.7's version and issue time
     (draw nothing there yet).
  2. Per location: name, address, coordinates (6 decimals, mono), the directions link as text, a QR code of the same
     link, parking, power, contact (name and phone), the sun (sunrise, sunset, golden and blue hours, with +1/−1
     marks), the forecast (high/low, wind, precipitation, conditions, "Data from MET Norway", fetched time), the
     safety box (emergency number large, hospital name, address, phone, distance, the 24-hour note).
  3. Scenes: number, heading, pages, location, frames, characters with their actors.
  4. Cast: name, characters, call, HMU ready, on set; phone/email only where 4.2's rule allows.
  5. Crew by department in call-sheet order: department call; each person's name, title, call, and phone/email only
     where allowed.
  6. Notes: general and safety.
  7. Footer on every page: page N of M, "Data from MET Norway" when a forecast is printed, "© OpenStreetMap
     contributors" when an OSM-sourced place or hospital is printed, and "Made with Storiiboard".
  - Times in JetBrains Mono, as on screen; text in Inter Tight; ink on paper (no grain, no colour fills except the
    golden-hour mark, which prints Burning Flame with ink text, and department tags if the storyboard PDF prints its
    colours that way). 1.5 pt rules, 10 pt uppercase mono labels, as the app's look on paper. No hex in components:
    take colours from design/tokens as the storyboard PDF does.
  - Long content flows onto more pages; a person's row, a scene's row and a location's block never split across a
    page break.
  - Never logged: phone numbers and addresses are private (CLAUDE.md, Security and privacy).
- **The directions link** (decision 4): Settings → App gets "Directions open in": Google Maps (default), Apple Maps,
  OpenStreetMap, kept in this computer's settings. The link is built from the location's place (coordinates) when it
  has one, else its address:
  - Google Maps: `https://www.google.com/maps/dir/?api=1&destination=<lat>,<lon>` (or the address, URL-encoded);
  - Apple Maps: `https://maps.apple.com/?daddr=<lat>,<lon>` (or the address);
  - OpenStreetMap: `https://www.openstreetmap.org/directions?to=<lat>,<lon>` (or the existing search link for an
    address only, `mapLink` in src/core/model/location.ts).
  It's a link only: the app never contacts Google or Apple. The Call sheet tile gets a "Copy map link" button per
  location that copies the same link (the clipboard as other "Copy link" buttons do: grep for one, 3.11).
- **QR codes:** `qrcode-generator`, pinned exactly at 2.0.4 (approved Nov 9; published Aug 2025; ships its own types,
  dist/qrcode.d.ts). Install with `npm install --save-exact qrcode-generator@2.0.4`. Draw the modules as vector
  rectangles in pdf-lib (no image), error correction M, with a quiet zone of 4 modules, about 25 mm square.
