# Brief 4.7: issuing a call sheet

For the builder (.claude/agents/builder.md). Written by the main session, Nov 10, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

A call sheet is live while it's drafted. Issuing it keeps the PDF exactly as sent, numbers it (version 1, 2, 3…),
prints the version and issue time in its header ("Revised" from version 2), and locks the day's scenes' shot numbers in
the same step, so slates and the script supervisor work from them. After that the sheet says "Changed since issued"
when anything printed on it changes, except the forecast (docs/PHASE4_DECISIONS.md, decision 5; CLAUDE.md, "Call
sheets"; docs/PLAN.md, "Phase 4 notes").

Builds on the call sheet tile and its PDF (4.1 to 4.6): src/core/model/callsheet.ts, src/features/callsheets/
(callSheetPdf.ts makes the PDF; exportCallSheet.ts waits for pending edits and builds from the store; callSheetName.ts names the file; the header leaves its top-right spot free for this milestone), and the Assets PDFs of 3.11 (src/core/model/attachment.ts, src/features/assets/: a
PDF is a `media` record of kind `pdf` whose bytes live in `media_files` by SHA-256; Open makes a read-only copy and
opens it through src-tauri/src/open.rs; Save a copy). The scene lock is 1.6's `numbers_locked` (src/core/model/
storyboard.ts `sceneFields`; read how the Scenes tile sets it). Read docs/briefs/4.1-call-sheet.md to 4.6-pdf.md first.

## Decisions that apply

- **Issue** (a primary button in the Call sheet tile's top row, beside Export PDF): one op group, one ⌘Z, which:
  1. makes the PDF with 4.6's code, for the paper chosen, with the header's top-right spot now printing
     "Version 1 · Issued Mon, Nov 16 18:04" (and "Revised · Version 2 · Issued …" from version 2), the issue time in the
     sheet's "Times in" zone (4.3) with the zone's short name, or this computer's zone and its name when none;
  2. stores the bytes in `media_files` (as 3.11 stores an attached PDF; the same 50 MB cap) and creates a `media`
     record of kind `pdf` under the `callsheet` record (made in the same group if the day has none yet), with props
     `issue_version` (1, 2…), `issued_at` (ISO), `issued_by` (the author as ops record it), `fingerprint` (below),
     `source_name` (the file name 4.6 gives, with " v2" before ".pdf" from version 2) and the usual `file`/`byte_size`;
  3. sets `numbers_locked: true` on each live scene of the day that isn't locked yet (the ones already locked are left
     alone, so undoing the issue unlocks only what it locked);
  - Undo takes all of it back (the record goes; the bytes stay in `media_files` until Clean up, as an attachment's
    do); redo brings it back. A version number is the highest live issue's plus one, so an undone issue's number is
    used again.
  - Issuing is refused (with words, nothing changed) when the day has no date, or the project file can't be written.
  - It doesn't send anything to anyone (publishing is Phase 9); after issuing, the tile offers "Save a copy" of the
    issued PDF (3.11's Save a copy) so the person can send it.
- **Issued versions** list under the top row: "v2 · Issued Mon, Nov 16 18:04 · Open · Save a copy", newest first;
  Open as 3.11 opens a PDF (a read-only copy). A version can't be deleted on its own in 4.7 (it goes with its day, or
  with an undo).
- **"Changed since issued"** (decision 5): a `fingerprint` of everything the PDF prints except the forecast (weather
  values, its fetch time and expiry) and except the issue header itself: a stable JSON of the sheet's data
  (`callSheet(...)` plus what the PDF adds: the directions links, paper is NOT included, the language is NOT included),
  hashed with SHA-256 (the app already hashes for media_files: reuse that). The tile shows, when the latest issue's
  fingerprint differs from the live one: "▲ Changed since issued (v2)" in the warning style (Truffle, with the ▲ cue),
  and the Issue button reads "Issue version 3". When they match: "Issued · v2", the button "Issue again" (disabled
  with words: "Nothing has changed since version 2").
  - Sun times count (they change with the date or place); the hospital, contacts, calls, notes, scenes and people
    count; the forecast doesn't.
  - Changing the app's language or paper doesn't count.
  - An approval current before an upgrade stays current after it (CLAUDE.md, Kevin Nov 9): the same goes here; a
    future change to the fingerprint's contents must not make old issues read as changed. So version the fingerprint:
    store `fingerprint_version: 1` with it, and compare only same-version fingerprints (a different version reads as
    unchanged). Say so in a comment.
- **History:** "Issued the call sheet for Mon, Nov 16 (version 2)" in en and es, never listing the PDF's contents;
  the lock reads as part of the same step.
- **Docs:** docs/SBD_FORMAT.md, a section "Issued call sheets (4.7)" for the media props and the fingerprint (additive,
  no schema number).

## Tests to add

- Vitest: the issue's change list (media record, version, lock only unlocked scenes, the callsheet made when missing);
  version numbering (after an undo the number is reused; the highest live plus one); the fingerprint stable across
  key order, unchanged by forecast changes, language and paper, changed by a call time, a note, a scene added, a
  hospital, a contact switch; fingerprint_version mismatch reads as unchanged; the header text for v1 and v2 in en and
  es; refusal with no date.
- Playwright (Chromium): issue a day; the versions list shows v1; the day's scene reads locked in the Scenes tile;
  change a call time → "Changed since issued (v1)"; Issue version 2 → "Revised" in the PDF's text; ⌘Z takes v2 off
  and the warning comes back; Save a copy writes the issued bytes (compare with what was stored).
