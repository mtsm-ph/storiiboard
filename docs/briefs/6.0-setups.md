# Brief 6.0: setups

Phase 6's first milestone (docs/PLAN.md, "Phase 6 milestones"; docs/PHASE6_DECISIONS.md, decision 3). Read CLAUDE.md
first, then decision 3 and CLAUDE.md's "Bird's-eye view" rules. Stay on the branch that is checked out.

## Goal

A setup is one camera position and lighting state; several frames can share one. After this milestone a person can
make setups in a scene, put frames in them, and see them listed in the Setup section. No plan is drawn yet (6.2).

## Decisions that apply

- A setup is a `setup` record under its scene (the record type already exists in src/core/model; find what is there
  and what already reads `setup_id`: src/core/model/shootDay.ts counts frames sharing a `setup_id` once).
- **Numbered within the scene: Setup 1, Setup 2, Setup 3. Never lettered** (shot numbers use the letters: 12A). The
  number is the setup's place among its scene's live setups, in the scene's order of children. It is worked out,
  never stored, and never changes with the language (the word "Setup" goes through `t()`; the number is mono).
- A setup may have a name typed by hand (`name` prop, empty by default): "Setup 2 · Window side".
- A frame joins at most one setup: the shot's `setup_id`. A frame with none is a setup of its own, as today.
- A frame's setup must be in the frame's own scene. Every reader treats a `setup_id` naming a setup in another
  scene, a trashed setup or nothing as "no setup" (one function in src/core/model, used everywhere, shootDay.ts
  included). Moving a frame to another scene unsets its `setup_id` in the same op group.
- Deleting a setup moves it to the Trash (trashed_at and trashed_by through an op; undo and Restore bring it back).
  Its frames keep their `setup_id` and simply read as "no setup" while it is trashed, so restoring it brings the
  membership back without touching the frames. The Trash lists setups under their scene, with a type filter entry.
  Trashing a scene takes its setups with it and restoring brings them back, as its frames do.
- Every change is an op through src/core/ops, one op group per action (one ⌘Z each), with a History summary line in
  en and es (src/features/history/summary.ts): setup added, renamed, reordered, deleted, restored; frames added to
  or taken out of a setup.
- No schema change and no new prop beyond `setup.name` and the existing `shot.setup_id`. If `setup_id` or the
  `setup` type turn out not to exist as described, stop and report; do not add a table or record type.
- JSON and CSV export must still round-trip (setups and `setup_id` included); add the round-trip case to the
  existing export tests. Do not add columns to any export in this milestone.

## What to build

1. Model, src/core/model/setup.ts (+ test): the scene's live setups in order with their numbers; a frame's setup
   (the one reader described above); a setup's frames; the edits (add, rename, reorder, delete, join, leave, new
   setup from frames) as op lists, as src/features/schedule/dayEdits.ts does for shoot days.
2. The Setup section goes live: in src/app/shell/workspaces.ts the `setup` workspace's `phase` becomes null (as
   Storyboard's and Production's are), so it is no longer muted in the sidebar. Its other tiles (plan, layers,
   selection, frames, library) stay placeholders; their notes say "Phase 6".
3. A Setups tile in the Setup workspace's default layout (its left column, where a list fits): scenes in board order
   ("SC 04  Scene name"), under each its setups ("Setup 1 · name", how many frames, the frames' shot numbers in
   mono). Add setup (per scene), rename in place (src/ui/EditableTitle), reorder by drag and from the keyboard,
   Delete to the Trash. Selecting a setup shows its frames (small pictures with shot numbers, read live from the
   board's records) with "Take out of setup", and a way to add frames of that scene that have no setup. Empty
   states in words. Everything keyboard reachable, labels on icon buttons.
4. On the storyboard: with frames selected, the context menu (and the "/" or command list if frames' actions are
   there) offers New setup from selection (only when all are in one scene), Add to setup ▸ (that scene's setups) and
   Take out of setup. A frame in a setup shows a small mono tag "S2" style marker only if the board already has a
   place for such tags; otherwise leave the board's frames as they are and say so in the report.
5. The Inspector (src/features/storyboard/InspectorView.tsx): a Setup row for the selected frame: a Select with "No
   setup", the scene's setups by number and name, and "New setup". Keep the "Bird's-eye · Phase 6" row.
6. Design: build from src/ui and the semantic token classes, no hex values; selection is an ink fill; mono for
   numbers; no radius, no shadow.
