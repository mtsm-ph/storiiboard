# Brief 5.12: attaching a company with a logo works in the installed app

From the desktop gap audit (docs/DESKTOP_GAPS.md, A1; Kevin, Nov 13). Read CLAUDE.md first. Stay on the branch that
is checked out (`fix/5.12-company-logo`).

## The bug

`logoFile` in src/app/company/companies.ts turns a company logo's `data:image/png;base64,…` URL into a File with
`fetch(logo)`. The installed app's content security policy (src-tauri/tauri.conf.json: `connect-src 'self' ipc:
http://ipc.localhost`) refuses a fetch of a `data:` URL, so Attach company and Update from profile
(src/app/project/ProjectCompanyFields.tsx:96) fail whenever the company has a logo. The tests never saw it: the dev
server sends no CSP.

## The fix

- `logoFile` decodes the data URL itself (split at the comma, `atob`, bytes into a Uint8Array), with no `fetch`. It
  can stay async so callers don't change. A string that isn't a base64 `data:` URL throws a plain Error the caller
  already shows; don't log the URL. The MIME type comes from the URL's header, PNG when absent.
- Do not change the CSP.
- Comment the why in one or two lines (the CSP), since people will fork this.

## Tests

- Vitest, next to companies.ts (add to its test file if one exists): `logoFile` gives back the exact bytes and type
  of a small PNG data URL, with `fetch` stubbed to throw so the test fails if it is ever used again; a malformed
  string rejects.
- A guard in Vitest, src/app/cspFetch.test.ts: read every .ts and .tsx file under src (not tests) and find each
  `fetch(` call. Each must be on a short allowlist in the test, keyed by file, with a reason (today: bundled font
  and asset URLs imported with `?url`, which are same-origin; dev-only code behind `import.meta.env.DEV`). A new
  `fetch(` anywhere else fails with a message naming the CSP's `connect-src` and docs/DESKTOP_GAPS.md. Build the
  allowlist from what is in the code now; if any existing call is not same-origin or dev-only, stop and report it
  rather than allowlisting it.
