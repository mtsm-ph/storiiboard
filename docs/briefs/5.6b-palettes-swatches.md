## Decisions that apply

- **A palette from a board** (decision 9: on the device, the existing palette code): a board linked to a scene (5.4's
  links) offers "Make palette from this board" (the board's strip, and the scene's palette editor offers "From a
  board" listing the boards linked to that scene). It reads the board's pictures (picture items, video cards' posters
  and shot cards' frames on it, each weighing the same, through the same reading and clustering as frames:
  extract.ts's per-picture Lab points and paletteFromFrames, letterbox bars left out), with the palette's size and
  locked swatches kept as the editor's Generate keeps them. It sets that scene's palette in one op group (undoable),
  exactly as Generate does. A board linked to several scenes asks which; one with no pictures says so and changes
  nothing. Reading uses the stored pictures (2560 px), never originals.
- **Swatches export** from a scene's palette (the palette editor's menu and a palette card's strip) and from a
  brand-kit card (its colours):
  - **PNG strip:** one row of equal swatches in order, each with its hex below in JetBrains Mono (and the scene's
    heading or the company's name above), on paper, ink text; 2400 px wide; drawn with the canvas, sRGB. Through the
    export registry and dialog like the other formats (src/features/export/), files to disk through src/core/storage.
  - **Adobe Swatch Exchange (.ase), written by our own code** (decision 9: a small, documented binary format; no
    dependency): big-endian; signature "ASEF", version 1.0 (two u16: 1, 0), the block count (u32); a group-start block
    (0xC001) named after the scene heading or company, then one colour-entry block (0x0001) per swatch: block length
    (u32), name length in UTF-16 code units including the terminating null (u16), the name in UTF-16BE with the null,
    the colour model "RGB " (four ASCII bytes), three f32 values 0–1, and the colour type (u16: 2, normal); then the
    group-end block (0xC002, length 0). Each swatch is named by its hex ("#DF5E27"). Put the writer in
    src/core/model/ (pure, tested byte for byte) with a comment naming the format's layout.
  - File names follow the app's language ("SC 04 palette.png", "SC 04 palette.ase"; names.ts's safe-name rules).
- Every word through t()/tn(), en and es. History names "Made SC 04's palette from Camera board".

## Tests to add

- Vitest: the .ase writer byte for byte for two swatches (signature, version, block count, group start and end, each
  entry's length, UTF-16BE name with its null, "RGB ", the floats, type 2); a palette from a board with three
  pictures (equal weighting; locked swatches kept; the size kept) in one op group, undo restores the old palette; a
  board with no pictures changes nothing; a board linked to two scenes asks; video posters and shot cards' frames
  counted; the PNG strip's size and swatch order; file names in en and es.
- Playwright (Chromium, `?files=memory`): link a board with pictures to a scene, make its palette from the board, the
  scene's palette editor shows it, ⌘Z restores the old one; export swatches as .ase and PNG and read the files back
  (the .ase's signature and swatch count; the PNG's width); axe light and dark. No console errors.
