# Brief 6.15, review fixes

Read docs/briefs/6.15-pointer-reorder-b5-b6.md first: this continues it, same rules. Nothing high. Fix 1 to 6.

1. **(Medium) A page drop can land outside the visible list** (src/features/moodboards/PagesPanel.tsx near 23 and
   79): the drop area is the whole `<ol>`, which runs past the scroll box that shows part of it, so in a deck long
   enough to scroll, dragging over the panel's header or controls counts as inside, the bar is drawn over them and
   a release moves the page to a row nobody can see. Clip the drop area to the visible scroll box; outside it a
   release writes nothing. Add edge auto-scroll while dragging (near the top or bottom edge the list scrolls, at a
   steady modest speed, stopping at its ends), so a page can be taken past what is shown.
2. **(Low) A scroll during a drag leaves a stale place:** recompute the drop place on `scroll` of the list (and
   after each auto-scroll step) from the last pointer position, so the bar and the target never disagree with
   what is under the pointer.
3. **(Low) Two pointers drive one drag** (src/ui/useRowDrag.ts near 67-86): remember the pointer id at press and
   ignore every other pointer's moves, ups and cancels until that one ends. The Setups tile's behaviour for a
   single mouse stays exactly as it is.
   Tests for 1 to 3 in e2e/decks.spec.ts (new tests): a long deck scrolled partway, a release over the header
   writes no step; a drag held at the bottom edge scrolls the list and drops on a page that wasn't visible; a
   second pointer's events during a drag change nothing.
4. **(Medium) The lint rule misses common shapes** (eslint.config.js): spread props (`const p = { draggable: true,
   onDragStart }; <li {...p}>`, or a hook returning that), a capitalised component that forwards `draggable` to
   a DOM node, `React.createElement('li', { draggable: true })`, `addEventListener` with a template literal or a
   variable event name, `el['draggable'] = true`, `toggleAttribute('draggable')`, `Object.assign(el, { draggable:
   true })`, `event['dataTransfer']`. Keep the ESLint rule and ADD a Vitest text scan beside
   src/app/cspFetch.test.ts (same style): every file under src (not tests) that mentions `draggable` (other than
   literally `draggable={false}` / `draggable: false`), `onDragStart`, `onDragEnd`, `onDrag` as a whole word,
   `dragstart`, `dragend`, `setDragImage`, or `dataTransfer` must be in an explicit list in the test with its
   reason: the react-konva files (Konva's own dragging: say so per file) and the OS-drop files (the same list as
   eslint's `OS_DROP_FILES`; keep one source of truth if eslint.config.js can import it, otherwise the test
   asserts the two lists are equal by reading eslint.config.js as text). A file leaving the list or a new file
   mentioning any of these fails with the message about pointer events. Also: `Identifier DragEvent` must not fire
   on `KonvaEventObject<DragEvent>` in react-konva files; the allowlist must not let `dataTransfer` be passed on
   or assigned (`take(event.dataTransfer)`, `dt = event.dataTransfer`).
5. **(Low) B5** (src-tauri/src/open.rs near 366-382): (a) a `Backups` folder that is a symlink or a Windows
   junction is now refused though backups still write through it (someone who moved backups to another disk):
   resolve it instead (canonicalize) and open the resolved folder, provided it is a directory; (b) so that nothing
   can ever be launched, reveal rather than open: use the opener's reveal on the folder (as `reveal_original`
   does) if that shows the folder's contents or the folder selected in its parent on each system, whichever the
   plugin gives; if reveal can't show a folder acceptably on one system, keep `open_path` there and re-check
   `is_dir` on the resolved path immediately before the call. Say what each system will show. Unit tests for the
   path logic.
6. **(Low) A single-file export stopped after the Save dialog leaves its path writable for the session**
   (src-tauri/src/export.rs near 136: `export_choose_file` remembers the path until a write): end it the same way
   as 6.15's folder run (the page's `finally` ends the run for a file target too), with a Rust test and a Vitest
   test as for folders.
