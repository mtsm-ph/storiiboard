# Brief 6.3: the library (plan icons as items with real sizes)

Phase 6, milestone 6.3 (docs/PLAN.md; docs/PHASE6_DECISIONS.md decisions 2, 8, 13). Read CLAUDE.md first (its
"Bird's-eye view" rules), then those decisions, then the briefs of what is already built: docs/briefs/
6.2a-plan-real-units.md and 6.2b-doors-rooms-copies.md (the plan host in src/features/birdseye/plan, the three
levels, "This setup only"), and docs/briefs/canvas-core-map.md. Stay on the branch checked out.

## Goal

The Library tile goes live: the kit's plan icons (src/ui/icons/plan, 68 SVGs, `PLAN_ICONS` in planIcons.ts) can be
placed on a plan as items with real default sizes, by pointer or keyboard. This milestone places set pieces, grip
hardware, sound and production items. Cameras, lights, flags and diffusion, north and the sun, cast marks and the
measure tool come in their own milestones: their icons show in the Library, muted, with the words "Coming in this
phase" (through `t()`), and cannot be placed yet.

## Decisions that apply

- An item is a `plan_item` of `kind: 'icon'` with `icon` (the icon's id, for example `set-art/table`), geometry in
  metres as every plan item, an optional `name` and `height_m`. Remove `set_piece` from the kinds in
  docs/SBD_FORMAT.md's schema 14 section (a set piece is an `icon` item whose icon is in the set-art group) and
  document the rest there.
- **Level by what it is** (decision 2): a set-art icon belongs to the room (it shows in every scene and setup that
  uses the room); every other icon here belongs to the setup shown. With only a scene shown (no setup), setup-level
  icons can't be placed: the Library says so in words. "This setup only" (6.2b's switch) works for set pieces.
- **Layer** (for 6.8): an item's department is its icon's group (`camera`, `lighting`, `grip`, `set-art`, `cast`,
  `sound`, `production`); worked out, never stored.
- **Never themed** (decision 13): icons are drawn exactly as the kit's SVGs, in light and dark. The note in
  docs/PLAN.md near line 2070 that Phase 6 recolours them is superseded: don't. Fix the comment in planIcons.ts that
  says Phase 5 draws them.
- **Default sizes, in metres (width × depth), editable after placing; a table in
  src/features/birdseye/plan/iconSizes.ts with a test that every placeable icon has one:**
  - set-art: table 1.5 × 0.8; chair 0.5 × 0.5; sofa 2.0 × 0.9; bed 1.5 × 2.0; car 1.8 × 4.5; stairs 1.0 × 3.0;
    column 0.4 × 0.4; plant-tree 0.6 × 0.6; counter-bar 2.4 × 0.6. (set-art/wall, door and window are the tools
    from 6.2: in the Library they select that tool instead of placing an icon.)
  - grip: c-stand 0.9 × 0.9; combo-stand 1.2 × 1.2; sandbag 0.4 × 0.25; apple-box 0.5 × 0.3; ladder 0.6 × 1.2;
    rostrum 1.2 × 2.4. (flag, floppy, diffusion-4x4, bounce, overhead-8x8 and neg-fill come in 6.5.)
  - sound: boom 0.6 × 0.6; lav 0.3 × 0.3; sound-cart 0.6 × 0.9; playback 0.4 × 0.4.
  - production: video-village 2.0 × 1.5; generator 0.9 × 0.6; distro-cable 0.6 × 0.4; basecamp 6.0 × 3.0;
    first-aid 0.5 × 0.5; parking 2.5 × 5.0; hazard 0.6 × 0.6; zone 3.0 × 3.0; note 1.5 × 0.5; snap-point 0.2 × 0.2.
    (north comes in 6.6, measure in 6.9.)
  - A zone is a named, resizable outline (its name drawn inside); a note shows its `name` as text. Both resize
    freely; every other icon keeps its drawn proportions unless Shift is held (the reverse of the core's default
    if that is what `keepRatio` gives: use `keepRatio`).
- No new dependency, table, record type or schema version.

## What to build

1. **The Library tile** (workspace tile id `library`; map it in src/app/shell/tileContent.tsx): icons grouped by
   department in call-sheet order with the group names through `t()`, each a button showing the SVG and its label
   (the SVG's `<title>`; labels are English in the kit: add them to en.ts and es.ts keyed by icon id and show the
   translation, falling back to the title). A filter field narrows by name. States in words: no plan shown; no
   room yet (set pieces need one: point at "Start the room"); a scene with no setup shown.
2. **Placing**: press and drag an icon from the Library onto the plan (pointer events, a ghost at real size under
   the pointer, grid snap as items have; never HTML5 drag and drop: it is off in the Windows app), or focus it and
   press Enter to place it at the middle of the view, selected; arrow keys then nudge as every item. Escape during
   a drag cancels. Placing creates the setup's `plan` record on demand in the same op group (as 6.2a does for
   rooms). One op group per placement.
3. **Drawing**: the plan host draws an `icon` item from its SVG at its real size (an image node from
   `planIconDataUrl`, decoded once per icon and shared; crisp at any zoom: render from the SVG, not a fixed-size
   bitmap, re-rasterising when the zoom settles as 5.7's `zoomSettle` does for items), with its name beneath in the
   UI face when it has one and the plan is zoomed in enough to read it. An unknown icon id draws a plain ink
   outline with a "?" and keeps its record untouched.
4. **The Selection tile** for an icon item: its label, name, width, depth, height (typed lengths), rotation, X
   and Y, "This setup only" for set pieces; several selected: the shared fields.
5. Copy, paste, duplicate, delete to the Trash, undo: through 6.2a's actions (extend them where they assume
   walls). History lines (en and es): placed, moved, resized, turned, renamed, deleted, restored, naming the icon
   ("Placed a sofa in Diner"). The Trash's Plan items list names them.
6. Export round trip (JSON; CSV unchanged).
