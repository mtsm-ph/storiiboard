# Brief 4.9: the map on a location

For the builder (.claude/agents/builder.md). Written by the main session, Nov 10, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

A location shows its place on a real map, drawn with react-konva from OpenStreetMap tiles fetched through Rust and
cached on disk, under OSM's tile policy; the pin can be dragged to where the crew should go (an entrance, a basecamp),
which saves the location's place (CLAUDE.md: Stack "Maps", Tool rules "Location map (4.9)", Network rules "Map
tiles"; docs/PHASE4_DECISIONS.md, "The map (4.9)").

Builds on: the address search's place (3.4: `latitude`, `longitude`, `map_name` on the location; src/core/model/
location.ts `mapPlace`, `MAP_PLACE_PROPS`; src/features/locations/), net.rs (the only HTTP path; HOSTS),
the service switch (4.0: src-tauri/src/services.rs `REGISTRY`, src/app/servicesStatus.ts), and react-konva (already a
dependency, used by the storyboard's canvases: grep for `react-konva`). Read docs/briefs/4.0-service-switch.md and
4.3-sun-times.md (for how a Rust command, its bridge and its browser fallback are laid out).

## Decisions that apply

- **Tiles:** `https://tile.openstreetmap.org/{z}/{x}/{y}.png` (host approved Nov 9). Add it to net.rs's `HOSTS` with its
  rule (the policy below) in the doc comment, and to the service switch's `REGISTRY` as `osm-tiles` with its words in
  servicesStatus.ts ("Map tiles (OpenStreetMap)", "The map on a location.", "Only the tiles of the map being viewed,
  kept on this computer for a week or as long as OpenStreetMap says.") and the README's operators section.
- **OSM's tile policy, all of it:**
  - the app's User-Agent (net.rs's), never a browser's; no `Referer` faking;
  - only the tiles in view (plus none ahead: no prefetching of neighbours or other zooms), never a bulk download, no
    "save for offline";
  - honour cache headers (`Cache-Control: max-age`, `Expires`); 7 days when there are none; send `If-None-Match` /
    `If-Modified-Since` when renewing a stale tile, and a 304 keeps it;
  - the credit "© OpenStreetMap contributors" always visible on the map, linking to
    https://www.openstreetmap.org/copyright (opened through src-tauri/src/open.rs as other links are);
  - at most 2 requests at a time to the tile server; zoom 0–19 only.
- **Rust:** a new src-tauri/src/tiles.rs:
  - `#[tauri::command] map_tile(app, z, x, y) -> bytes` (PNG), from the disk cache when fresh, else through net.rs (a new
    `get_bytes` beside `get_json`, same client, HTTPS, host check, User-Agent; with the conditional headers);
  - the switch asked first (`service_server(app, "osm-tiles")`; off: the usual `service-off:<code>` error, and the map
    says why in place of the tiles);
  - the disk cache under the app's cache folder (`app.path().app_cache_dir()`, a `tiles/` folder: `z/x/y.png` plus a
    small sidecar with the expiry and validators), never in a project; a cap of 200 MB, oldest-read deleted first, so
    it never grows without end; Settings → Storage shows its size and a Clear button (read how Storage lists the
    playback copies, src/app/project/StorageTile.tsx);
  - validate z/x/y ranges; refuse anything else; at most 2 in flight (a semaphore).
- **A tile provider of one's own** (CLAUDE.md): Settings → App (or Online services: pick the clearer and say which),
  "Map tiles from": OpenStreetMap (default) or "Your own tile server" with a URL template
  `https://…/{z}/{x}/{y}.png`. Setting one adds that one host to what net.rs allows for tiles only (kept in this
  computer's settings; Rust reads it from there, never from the page per request), HTTPS only, and Settings says right
  there that the app will contact that host for tiles. The OSM credit then reads "Map tiles: <host>" plus whatever
  attribution text the person enters. Validate the template strictly ({z},{x},{y} each once, https, a host name).
  If this makes the milestone too big, build it last and say so; don't drop the OSM policy work for it.
- **The map (page):** src/features/locations/LocationMap.tsx, react-konva:
  - in the location editor under the map place, about 100% wide × 220 px; Web Mercator tiles at the zoom that fits
    (start at 16 on the place); pan by dragging the map, zoom with buttons (+/−) and the wheel, keyboard: arrows pan,
    +/− zoom, all reachable and labelled;
  - the pin at the location's place; dragging it (or pressing "Move pin" then arrows, for the keyboard) and releasing
    saves the new `latitude`/`longitude` in one edit (one ⌘Z), keeping `map_name` but marking the place as moved by
    hand: a new prop `map_moved: true` (documented in SBD_FORMAT.md's location props, additive) so the sheet can say
    "Pin placed by hand"; a new address search pick clears it (with 3.4's `unpinnedBy`/MAP_PLACE_PROPS: add the prop
    there);
  - no place yet: the map isn't drawn; the existing "Search address" flow stays the way to get one;
  - tiles load through the bridge (src/app/mapTiles.ts); the browser build draws a plain grid with the pin (no tiles,
    nothing online), so tests are deterministic, and says "Map tiles show in the desktop app";
  - tiles failing (offline, refused, switched off): a grey tile and one line saying why, the pin still works.
- **Not in 4.9:** the map on the call sheet and PDF (4.10).

## Tests to add

- Rust: the URL; ranges refused; the cache (fresh read without a fetch, stale renewed with validators, 304 keeps, no
  headers → 7 days, the 200 MB cap evicts oldest-read); the switch off sends nothing; at most 2 in flight; the own
  provider's template validation and host check; all with an injectable fetch, never the network.
- Vitest: mercator maths (round trips, zoom limits, the antimeridian); the pin edit (one change, map_moved set, a new
  pick clears it); the credit always present; keyboard pan/zoom/move.
- Playwright (Chromium): a location with a place shows the map (browser grid) with the pin and the credit; moving the
  pin with the keyboard saves new coordinates (shown in the editor), ⌘Z puts them back; Settings → Online services
  lists map tiles.
- Screenshots: Settings changes (Online services lists a third service; Storage gains a line; App maybe): expect the
  `settings-*` screenshots to fail; don't regenerate.
