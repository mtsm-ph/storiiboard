# Brief 6.2a: the plan in real units (lengths, the canvas at scale, rooms and walls)

Phase 6, first half of milestone 6.2 (docs/PLAN.md; docs/PHASE6_DECISIONS.md decisions 1, 2, 7, 13). Read CLAUDE.md
first (its "Bird's-eye view" rules), then those decisions, then docs/briefs/canvas-core-map.md: a map of the canvas
core (`src/ui/canvas`) and its moodboard host, with the names this brief uses. Stay on the branch checked out.

## Goal

The Plan tile in the Setup section goes live: a person picks a setup (or a scene), starts its room, and draws walls
to scale with typed lengths, on paper, with a grid, rulers and a scale bar. Everything is a record and an op.
6.2b adds doors, windows, shared rooms and copies; 6.3 the library. Build nothing of those here.

## Decisions that apply

- **The file is always metres** (and degrees). The screen shows metres or feet by this computer's region (feet and
  inches in the US, metres elsewhere) with a Settings override, exactly as Weather units work (Settings → App; find
  that code and follow it: same place, same pattern, a "Plan units" choice: By this computer's region, Metres, Feet).
- **Lengths** (src/core/model/length.ts + test): `parseLength(text, unit)` to metres and `formatLength(m, unit)`.
  Accepts "3.5m", "3,5 m", "350cm", "12ft", "12'", 12' 6", 12'6, 6", "6in", and a bare number in the unit shown.
  Feet format as feet and inches to the nearest half inch (12' 6"), metres to the centimetre (3.50 m). Anything
  else returns null and the field refuses it with a short message; nothing is saved. Technical values in mono.
- **Three levels, each a `plan` record, an item's level is the plan it sits in** (decision 2):
  `kind: 'room'` under the project, pointed to by a scene's `room_id`; `kind: 'blocking'` under its scene;
  `kind: 'setup'` under its setup. A plan record is created the first time something needs it, never ahead. This
  milestone creates rooms and writes room-level items only; write the readers so the three levels already combine:
  one function gives the items a setup's plan shows, back to front: the scene's room's items, then the scene's
  blocking's, then the setup's own. Trashed plans and items are skipped; a `room_id` naming a trashed or missing
  room reads as no room (one reader, as `frameSetupId` in src/core/model/setup.ts).
- **A `plan_item`'s geometry** uses the same prop names as `board_item` (`x`, `y`, `width`, `height`, `rotation`,
  order by `sort_key`), but in metres. Props are listed in docs/SBD_FORMAT.md's Phase 6 section (written in 6.1):
  keep it in step, and add what this milestone settles (below).
- **A wall is one straight segment stored as a rotated rectangle**: `kind: 'wall'`, `width` is its length,
  `height` its thickness (0.1 m by default), `rotation` its direction, `height_m` its real height when set (not
  drawn; shown in properties). So the canvas core's move, rotate and resize work on it unchanged. Do not store
  `points` for walls; take `points` for walls out of SBD_FORMAT.md if 6.1 listed it that way (paths keep it).
- **Never themed** (decision 13): the plan is paper with ink in light and dark, as boards are: pass the canvas a
  fixed colour set (`fixedColours`, as BoardView passes `BOARD_COLOURS`); share those constants, don't copy the hex.
- No new dependency, table or record type. No schema version beyond 6.1's.

## What to build

1. **Model**, src/core/model/plan.ts (+ test): plan and plan_item fields with validation and defaults; the readers
   above (`sceneRoomId`, the plans of a setup, the items a setup's plan shows with each item's level); a scene with
   no setup still shows its room and blocking.
2. **The canvas core takes a scale, without changing what boards do** (src/ui/canvas; every new prop optional, the
   moodboard passing none, its tests and screenshots unchanged):
   - The plan host converts at its boundary: **1 canvas unit = 1 cm** (metres × 100), so the core's world constants
     (minimum size 8, nudge 1 and 10, paste offset, stand-off) land at sensible real sizes. Keep the conversion in
     one module (toCanvas, toMetres) and never store canvas units.
   - Host-supplied tools: today `Tool`, `PlaceTool`, `PLACED_SIZE`, ToolStrip's `TOOLS` and `toolForKey` are a closed
     set. Open them the smallest way that lets a host give its own tool list (id, label, icon, key, default size,
     and a "draws point to point" flag) while boards keep theirs.
   - An overlay slot or props for: a grid (0.5 m, or 1 ft when the screen shows feet; lighter every step, stronger
     every 1 m or 5 ft; hidden when lines would be closer than about 8 screen px), rulers along the top and left in
     the unit shown, and a scale bar bottom left that always shows a round real length (1 m, 2 m, 5 m; 5 ft, 10 ft)
     and its label. Grid snapping (to the 0.5 m or 1 ft step, with Alt held to snap finer or not at all, following
     how the core's item snapping already treats a modifier) alongside the existing item-line snapping.
   - Zoom: fit-to-content may zoom past 100% for a plan (`fitBounds`' maxZoom is 1 today); the zoom label for a
     plan shows the scale bar instead of a percentage. Limits wide enough for a 2 m prop table and a 60 m stage.
   - `CanvasItem` gains optional `locked` (not picked by click, marquee, Tab or select-all; still drawn) and
     `dim` (drawn at reduced opacity). Nothing sets them yet except tests; 6.8 and 6.9 use them.
3. **The plan host**, src/features/birdseye/plan/: its own items module (record → CanvasItem and back, in metres),
   actions (each one `applyWith` group, as src/features/moodboards/boardActions.ts: place, change geometry, nudge,
   reorder, delete to the Trash, cut, copy, paste, duplicate), a store for selection, viewport and tool per plan
   view. Reuse the generic core; do not import from src/features/moodboards except shared constants moved to a
   neutral place. Sections, connectors, pages and text items are not part of a plan.
4. **The Plan tile** (workspace tile id `plan`; map it in src/app/shell/tileContent.tsx): shows the setup selected
   in the Setups tile (lift that selection into a small store both tiles read, as src/features/schedule/shownDay.ts
   does for days; selecting a scene heading there shows the scene without a setup). States, in words: no project;
   no scene or setup selected; a scene with no room yet: a "Start the room" button that creates the room plan
   (named after the scene's location when it has one, else the scene) and sets the scene's `room_id` in one op
   group. Header: "SC 04 · Setup 2 · name" in mono for numbers.
5. **Walls**: the Wall tool (key W) draws point to point: click to start, each click ends a segment and starts the
   next, Enter or double-click finishes, Escape cancels the segment in progress. While drawing, the segment's
   length shows beside it in the unit shown and typing a length (any accepted form) then Enter sets it exactly along
   the current direction. Ends snap to other walls' ends and to the grid; Shift holds to 15° steps. A whole run is
   one op group (one ⌘Z). Walls draw as ink bars; joined ends meet cleanly at corners.
6. **The Selection tile** (tile id `selection`; live): for the selected item, its kind, name, length, thickness,
   height and rotation as typed fields (lengths through parseLength, refused when unreadable), X and Y; for several
   items, the fields they share. Each change an op. With nothing selected, the room: its name (editable) and how
   many scenes use it.
7. **Trash and History** for `plan` and `plan_item`, as `board` and `board_item` have them: src/core/ops/ops.ts
   (`TRASHED_BY_PEOPLE` and the Empty Trash types), src/features/trash/trash.ts and TrashTile (a Plan items type,
   listed under their scene or room), src/features/history/summary.ts (lines in en and es: wall drawn, moved,
   resized, deleted, restored; room started, renamed). Trashing a scene does not trash its room (other scenes may
   use it).
8. JSON and CSV export round-trip with rooms and walls (add to the existing round-trip test).
9. The placeholder tiles that stay (layers, frames, library) keep their "Phase 6" notes; remove the `plan` and
   `selection` notes' keys if nothing uses them any more.

## Not in this milestone

Doors, windows, shared rooms, "Make a separate copy", copying a setup's state (6.2b); icons and set pieces (6.3);
cameras, lights, marks, layers, underlay, measure, export. No change to what a board does or looks like. Do not
touch .github, .claude, src-tauri or package.json. Never regenerate baselines: if a screenshot differs, list it
(the default Setup layout isn't in the screenshots, so none should). No git commands that change anything.
