# Brief 6.9: underlay and measure

Phase 6, milestone 6.9 (docs/PLAN.md; docs/PHASE6_DECISIONS.md decision 12). Read CLAUDE.md first (its
"Bird's-eye view" rules; "Moodboards and decks": how pictures are stored), then decision 12, then the briefs of
what is built (6.2a to 6.8 in docs/briefs). Stay on the branch checked out.

## Goal

A floor plan or a location photo can sit under a room, set to scale by two points and a typed distance, so walls
can be traced over it. A measure tool draws dimension lines that read real distances.

## Decisions that apply (decision 12, with Kevin's: the underlay belongs to the room)

- **The underlay** is a `plan_item` of `kind: 'underlay'` in the ROOM's plan, with `media_id` (its picture) and
  geometry in metres as every item. Every scene and setup using the room sees it. A room may have more than one.
- **The picture is stored exactly as a board's pictures are** (5.1b; CLAUDE.md): at most 2560 px with a pointer
  to the original for full quality, never the original embedded; a small preview when zoomed out and the full
  picture only up close (5.7). Reuse that pipeline end to end (choose a file, drop from the OS, paste; the same
  `media` record kind, the same reading through Rust in the desktop app and the same stand-in in the browser
  build; missing media flagged as boards flag it). A PDF floor plan is not read in this milestone: say so in
  words when one is chosen ("Save it as a picture first"), and list it in the report as a question for Kevin.
- **Beneath everything, dimmed, locked**: it draws under every other item at 50% opacity and is not picked
  (the core's `dim` and `locked`), so walls are traced over it. The Layers tile (6.8) has its own "Underlay" row
  (Shown, Dimmed, Hidden, Locked; its default: dimmed and locked); unlocking it there lets it be selected, moved,
  resized (keeping proportions) and turned like any item, and deleted to the Trash. The room's menu gains "Add
  underlay…". Layers' state for the underlay row lives with the other layers' (this computer's settings).
- **Set to scale by two points and a typed distance**: with an underlay in the room, a "Set scale" action (the
  room's menu, the Layers row, and the Selection tile when the underlay is selected): click two points on the
  picture, type the real distance between them (any form src/core/model/length.ts reads); the underlay is scaled
  about the first point so that distance is true, in one op group. Until a scale has been set the underlay shows
  a quiet note ("Not to scale yet") in the Plan tile's header; whether it has been set is worked out from a new
  prop `scaled: true` written by the action (document it in docs/SBD_FORMAT.md's schema 14 section).
  A freshly added underlay is placed with its longer side 10 m, centred in the view.
- **Measure**: a `plan_item` of `kind: 'measure'`: one straight dimension line stored as walls are (a rotated
  rectangle: `width` is its length, `height` 0.01 m, `rotation` its direction), drawn as a thin ink line with
  end ticks and its length in the unit shown as an upright mono label at its middle; never themed. The Measure
  tool (the kit's `production/measure` entry in the Library selects it; key R if free: say which) draws point to
  point exactly as the Wall tool does (the run logic in src/ui/canvas/pathRun.ts: each segment a measure; typed
  lengths; Shift for 15° steps; ends snap to walls' ends, items' snap points and the grid). It belongs to the
  room (a wall-to-wall dimension is the room's); "This setup only" (6.2b) moves one into the setup's plan. Its
  layer is production. The Selection tile shows its length (typed: the start stays), rotation, X and Y.
- No new dependency, table, record type or schema version. No network.

## What to build

1. Model: underlay and measure fields and readers; the set-scale edit (pure: given the two clicked points in
   metres and the typed distance, the new geometry); level and layer rules extended; `WRITTEN_KINDS` and
   `unreadableAfter` cover both kinds.
2. The underlay: add (menu, drop onto the plan from the OS, paste), draw (beneath all, previews as boards),
   Layers row, unlock to edit, Set scale (a two-click gesture using the canvas's point-to-point run with exactly
   two points, then the app's small typed-question window opened on a setTimeout(0)), the header note.
3. The Measure tool and its drawing, Selection tile fields, Library entry.
4. History lines (en and es): underlay added, set to scale ("Set the underlay's scale: 3.50 m between the
   points"), moved, deleted; measure drawn, changed, deleted. Trash; export round trip (the picture's `media`
   record included: follow what boards do for JSON export of pictures). A room copy copies its underlays (the
   same `media_id`, not a second picture) and measures.
5. A `madeIn` guard on the deferred parts (the two-click gesture, the question, a drop).

## Not in this milestone
