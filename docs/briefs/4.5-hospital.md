# Brief 4.5: the nearest hospital, and the emergency number

For the builder (.claude/agents/builder.md). Written by the main session, Nov 10, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

A location gets a nearest hospital, found on a button press or typed by hand, kept on the location and printed in a
safety box on every call sheet there, with the emergency number for the location's country (docs/PHASE4_DECISIONS.md,
decision 2; CLAUDE.md, "Call sheets" and Network rules, "Nearest hospital").

Builds on: the address search (3.4: src-tauri/src/geocode.rs, src/app/addressSearch.ts,
src/features/locations/AddressSearch.tsx and findPlaces.ts, the `lookups` cache in src/core/storage/lookups.ts), the
service switch (4.0: src-tauri/src/services.rs), and the call sheet (4.1 to 4.4: src/core/model/callsheet.ts,
src/features/callsheets/). Read docs/briefs/4.1-call-sheet.md to 4.4-weather.md for what's there.

## Decisions that apply

- **Find nearest hospital** (a button in the Locations tile's location editor, under the map place; enabled only when
  the location has a place on the map, `mapPlace` in src/core/model/location.ts):
  - Nominatim, the same service as the address search (its id `nominatim` in the switch; already on `HOSTS`), only
    when pressed; never Google, never Overpass. Through net.rs, in a new Rust command (in geocode.rs or a new
    hospital.rs), sharing geocode.rs's one-request-a-second queue (`reserve()`) and asking `service_server` first.
  - The request: `/search` with `amenity=hospital` (Nominatim's structured amenity query), `format=jsonv2`,
    `extratags=1` (for `emergency`), `addressdetails=1` (for `country_code`), `limit=20`, and a `viewbox` of about
    25 km around the place with `bounded=1`. If that finds none, one wider try at about 75 km; no more.
  - The answer: up to five, those with `extratags.emergency = "yes"` first, then by straight-line distance (haversine
    in km, one decimal; miles where 4.4's weather units say US: src/app/weatherUnits.ts). Each: name, address (Nominatim's `display_name`
    shortened to its first parts is fine; say what you chose), coordinates, distance, `emergency` (yes, or unknown),
    phone if `extratags.phone` has one, and the country code.
  - Cached in `lookups` as kind `hospital_search`, `query_key` the place rounded to 3 decimals and the language;
    Find again replaces it, as Search again does. Update SBD_FORMAT.md's `kind` note.
  - In the browser build, a recorded answer (a fixture you write by hand under src/core/net/recorded/, as
    recordedSearch.ts does for addresses): nothing goes online in tests.
  - The list shows each with its distance; one without an emergency department known gets the note "Check it has a
    24-hour emergency room" (the words, plus a second cue; Truffle, the warning token, never orange). Picking one is
    the edit.
- **Kept on the location** (props, additive, documented in SBD_FORMAT.md's "Location props (3.3)" like `full_view`):
  `hospital_name`, `hospital_address`, `hospital_phone`, `hospital_latitude`, `hospital_longitude`,
  `hospital_emergency` (true, or missing for unknown). Picking a found one sets them in one edit (one ⌘Z); the fields
  are also editable by hand in the location editor (name, address, phone), each one edit when left; Clear hospital
  takes them all off in one edit. Phone is private like every contact: never logged; History may show it like the
  location's contact phone already is (check summary.ts for how `contact_phone` is shown and do the same).
- **Country and the emergency number:**
  - A location prop `country_code` (ISO 3166-1 alpha-2, upper case). Set from the picked hospital's country code
    when the location has none; editable by hand in the location editor (a Select of countries, names from
    `Intl.DisplayNames` in the app's language, plus "Not set").
  - A table in the code, src/core/model/emergencyNumbers.ts, country → the number to call for an ambulance, with a
    comment that it's editable and that each entry should be checked against the country's own sources. Exactly these
    (the main session's list; Kevin checks it):
    - 911: US, CA, MX, and US territories PR, GU, VI.
    - 112: every EU country, plus NO, CH, IS, IN.
    - GB: "999 or 112"; IE: "112 or 999".
    - AU 000; NZ 111; JP 119; BR 192; CO 123; CL 131; PE 106; AR 107.
    Countries not in the table: "Emergency number: check locally" (never guess 112).
  - The location editor shows the number for its country beside the Country field.
- **On the call sheet:** a Safety box per location (a section near Locations, or inside each location's block; pick
  the clearer and say which): the emergency number (large, mono), the hospital's name, address, phone and distance,
  "24-hour emergency room" when known, the check note when not, and "No hospital set: find one on the location" when
  none. The call sheet's safety notes (4.1) stay where they are.
- **Credit:** Nominatim's results are OpenStreetMap data: the location editor's existing credit line covers the
  search (`location.mapCredit`); the call sheet's safety box adds "© OpenStreetMap contributors" when its hospital came
  from a search (keep a `hospital_source: "osm"` prop to know; by hand: none).

## Tests to add

- Rust: the URL (amenity, viewbox, bounded, extratags, addressdetails, limit) from a place; the answer's reading from
  the fixture (emergency yes/unknown, phone, country code); the switch off sends nothing (injectable fetch, as in
  services.rs); the one-a-second queue shared with the address search.
- Vitest: sorting (emergency first, then distance), at most five, distance in km and mi; the cache (fresh read, Find
  again replaces); the emergency table (each listed country, one not listed, the UK's two numbers); the location edits
  (pick sets all in one change list, clear takes all off, hand edits, country from the hospital only when unset); the
  safety box data in callsheet.ts for each case; every word in en and es.
- Playwright (Chromium): a location with a place finds hospitals (recorded), picks the first, the call sheet shows
  the safety box with the number and the hospital; Clear takes it off; a location without a place has Find disabled
  with words saying why.
