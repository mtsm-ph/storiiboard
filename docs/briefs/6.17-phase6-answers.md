## 2. Symbol icons: a true-size outline with the symbol in the middle, never stretched

Kevin's rule (Nov 14): a footprint whose drawing is **a symbol or a letter** (Parking's P, Basecamp's tent, Video
village's monitor, Generator's bolt) draws as **an outline at the item's true size, with the symbol at its own
proportions in the middle, never stretched**. Drawings of **the thing itself seen from above** (sofa, bed, car,
stairs) keep stretching to their real footprint, as now.

- Find how icons are classed today (src/features/birdseye/plan: library.ts, iconSizes.ts, iconBoxes.ts,
  iconDraw.tsx; 6.6's review added "symbol icons in their own proportions": build on that, don't add a second
  mechanism). Each of the 68 library icons gets an explicit class in the table, `symbol` or `top-view`: no icon is
  classed by a guess at draw time. A test fails if an icon has no class.
- You decide each icon's class from its drawing (read the SVG source in src/ui/icons or wherever the kit's plan
  icons live): a letter, a pictogram of the thing seen from the side or front, or an abstract sign is `symbol`; a
  plan view of the object is `top-view`. Kevin's four are `symbol`, his other four `top-view`. **Put the full list
  of 68 with your class for each in the report** so Kevin can overrule any.
- A `symbol` item draws: a rectangle outline at the item's real width and depth in metres (ink, the same thin
  line weight icons already use, turning with the item); inside it the symbol scaled uniformly to fit with a small
  margin, centred, never stretched and never larger than its natural proportions allow. A very long thin footprint
  therefore shows a small symbol in a long outline: that is right. The symbol turns with the item as it does
  today (keep today's behaviour for rotation; say what it is).
- The same on the plan, in the PDF and in the PNG (src/features/export/planRender.tsx and what it shares with the
  canvas: one drawing path if there is one). The Library tile's thumbnails stay as they are. Hit-testing,
  selection handles, snapping and the legend use the true footprint, as now.
- Tests: Vitest on the geometry (a 6 × 2.5 m Parking draws an outline 6 × 2.5 and a symbol whose width:height
  equals its natural ratio, centred; a `top-view` sofa still stretches); the class table is complete; an
  end-to-end or print test that a symbol item's printed outline has the footprint's size (extend
  planPrint.test.ts's style). Existing tests of icon drawing keep their assertions; if one asserts the old
  stretched or bare-symbol drawing for a symbol icon, this brief asks for that change: name each.
- Screenshot baselines (e2e/visual.spec.ts) must not change: check that no baselined screen shows a plan with a

## 3. Per-department prints

Today a setup's plan exports as PDF and PNG with everything on it, and as two packets (a scene: a page per setup; a
shoot day: its setups in the day's order). Kevin, Nov 14: **add per-department prints.**

- In the Export dialog, the plan formats (setup PDF, setup PNG, scene packet, shoot-day packet) gain one choice,
  **Departments**: `Everything` (default: exactly today's output, byte for byte where tests compare), one of the
  plan's departments (the layers of 6.8, src/core/model/planLayers.ts: camera, lighting, grip, art, cast blocking,
  and any other layer the model has, in its order), or `Each department`.
- A department's print shows: the room always, as context (walls, doors, windows, the underlay if it prints today,
  north, the scale bar and the sun if they print today); that department's items in full (with their cones, beams,
  paths and labels); other departments' items left out entirely, not dimmed. The art department's print is the
  room plus set pieces. The legend lists only what is drawn; the title block names the department after the
  setup's name ("Setup 2 · Lighting"); the file name gains the department's stable id (not its translated name,
  CLAUDE.md's rule on file names other tools rely on doesn't apply here: export names follow the language, so use
  the translated name, sanitised as other export names are).
- `Each department`: a PDF gets a page per department that has at least one item in that setup, in the layers'
  order, after nothing else (no "everything" page); a packet gets those pages setup by setup; PNG writes one file
  per department. A department with nothing in a setup is skipped; if none has anything, the export says so
  instead of writing an empty file.
- The choice is this computer's setting for the dialog (as the dialog's other choices are remembered, if they
  are; otherwise not remembered), never stored in the project.
- The print path decides what to draw from the layer of each item, the same function the Layers tile uses: no
  second table of which item belongs to which department.
- Words through `t()` with en and es (Spanish is the builder's until Kevin's glossary pass: list the new Spanish
  strings in the report).
- Tests: Vitest on the page plan (which pages, which items per page, legend rows) for one department and for Each;
  the written PDF of a lighting print contains the light's beam and not the camera's cone (read the PDF as
  planPrint.test.ts does); `Everything` is unchanged (existing tests untouched and green); end to end: choose
  Lighting in the dialog, export, the file name and page count are right.
