## The decision (the main session's, told to Kevin): every step gets its own later time

No format change. In ONE place in the op layer, the time an op group is given is strictly later than the time of
every op group already in that file: `at = max(now, last + 1 ms)`, where `last` is the newest op group time the
file holds (read once when the file is opened, then kept as groups are committed; per open file, never a global
shared between two projects). It applies to every writer of a group: apply, undo, redo, restore, Empty Trash's
purge, and any write that stamps `trashed_at`, `updated_at` or `created_at` from the group's time. So "trashed at
the same time by the same person" is true only of records trashed in the same step, everywhere it is used.

- A clock that jumps back (a time-zone change, a corrected clock): times keep rising from the last one, a
  millisecond at a time, until the clock passes them. Say so in the comment.
- A file whose newest op time is in the FUTURE (another computer's clock was ahead): the same rule; nothing is
  rewritten.
- The caller's injected `now` (tests pass one) still works: the rule is applied to what it returns.
- The time is not a secret or personal data; nothing new is logged.
- If the op layer cannot know the file's newest time cheaply at open (it already reads `lastOpTime` for the Saved
  sign, src/core/ops/ops.ts: one indexed query), say what it costs.
