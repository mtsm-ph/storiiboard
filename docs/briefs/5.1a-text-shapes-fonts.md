# Brief 5.1a: text, sticky notes, shapes in any colour, and fonts

For the builder (.claude/agents/builder.md). Written by the main session, Nov 10, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

The first half of 5.1 (docs/PLAN.md, "Phase 5 milestones"; Kevin's answers in docs/PHASE5_DECISIONS.md, decision 7):
on a board, text boxes, sticky notes and shapes in any colour, with text in the bundled fonts or this computer's,
listed through Rust with font-kit. Builds on 5.0's canvas core (src/ui/canvas/) and boards (src/features/moodboards/;
read docs/briefs/5.0-canvas-core.md and the code first). 5.1b adds pictures, video cards and links.

## Decisions that apply

- **Items** (`board_item` kinds, props documented in docs/SBD_FORMAT.md's "Boards" section and its Change log; no
  migration, no schema_version change):
  - `rect` (5.0) gains `fill` and `stroke`; new shapes `ellipse`, `triangle`, `diamond`, with the same props. Colours
    are stored as `#RRGGBB` strings: board content is the person's, so it doesn't follow the theme and prints as seen.
    A rect from 5.0 without `fill` keeps drawing as it did (raised surface, ink outline).
  - `text`: `text`, `font_family`, `font_weight` (100–900), `font_italic`, `font_size` (world units), `color`,
    `align` (left, center, right). The box's width wraps the text; its height grows with it.
  - `sticky`: a square note with `text`, `color` from a fixed set of six sticky colours, each light enough that ink
    text on it passes AA (4.5:1; test it), and the font as a text box has (default Inter Tight).
- **Tools:** Text (T), Sticky (S), and a Shape tool (O for ellipse; the strip's shape button opens the four shapes),
  beside 5.0's Select, Hand and Rectangle. Click places an item and, for text and sticky, starts editing it.
- **Editing text:** double-click or Enter on a selected text or sticky item edits it in place: a textarea over the
  item, matching its transform, font and zoom; Escape or a click outside ends editing and writes one op group (no op
  per keystroke). An empty new text box disappears when editing ends with nothing typed (no op). ⌘Z while editing
  undoes typing in the field, not project edits (as the app's other fields do).
- **Properties:** with items selected, a properties strip (in the tile, under the tools) shows what they share: fill
  and stroke (shapes), colour (text), sticky colour, font family and style, size, alignment. A change applies to every
  selected item in one op group. The colour control: the six sticky colours or, for shapes and text, a set of swatches
  plus a hex field and the system colour picker (`<input type="color">`). No new colour library.
- **Fonts** (decision 7):
  - The bundled fonts first (src/ui/fonts: Inter Tight, JetBrains Mono, Archivo, Bodoni Moda, Jost, Outfit), then this
    computer's, from a new Rust module `src-tauri/src/fonts.rs` using **font-kit 0.14.3** (approved by Kevin, Nov 10;
    pin it exactly: `font-kit = { version = "=0.14.3", ... }`). Its commands: the list of families with their styles
    (name, weight, italic, PostScript name), read once per session and cached; and a font's bytes plus its OpenType
    `fsType` bits (from the OS/2 table) for one PostScript name.
  - Each font crate font-kit brings in must have been released at least two weeks before today (crates.io's API has
    the dates): check the new entries in Cargo.lock and, if one is newer, `cargo update -p <crate> --precise <older>`.
    Say which versions you ended on. Choose font-kit's features so Linux CI builds with no new system packages
    (`source-fontconfig-dlopen` if it needs it; Linux isn't shipped, only tested).
  - The page draws a system font by loading its bytes from Rust into a `FontFace` (so it doesn't depend on what the
    webview lets pages see), once per font per session. Font bytes are never stored in the project: a board stores
    only family, weight and italic.
  - A board that names a font this computer lacks draws it in Inter Tight and says so once on the board ("Brand Sans
    isn't on this computer; showing Inter Tight"), and the properties strip shows the missing name.
  - `fsType` is read and kept with the font for 5.6's PDF rule (never embed a font whose bits forbid it); 5.1a only
    reads it and tests the parsing. Bits: 0x0002 restricted (no embedding), 0x0004 preview and print, 0x0008 editable,
    0x0100 no subsetting, 0x0200 bitmap only.
  - Adobe Fonts Kevin has activated should appear (they register with the system). Write a test-free note in the
    report on how font-kit reaches them on macOS (CoreText) and Windows (DirectWrite), so the main session can check
    by hand.
  - The browser build has no Rust: it lists only the bundled fonts.
- **Text on the canvas** stays readable: ink on paper by default, whatever the theme (board content isn't themed),
  the theme's colours only for the canvas around the items, the selection and handles.
- Every visible word through t()/tn() in en and es.

## Tests to add

- Rust: the fsType parser (each bit; a missing OS/2 table); the family list on this computer isn't empty and lists
  Arial or Helvetica on Windows or macOS (skip on Linux); bytes for a listed PostScript name.
- Vitest: each new kind's props and defaults; a property change on three items is one op group; sticky colours pass
  AA with ink; text editing writes one group; an empty new text box writes nothing; a missing font falls back and is
  reported once; the bundled-only list in the browser build.
- Playwright (Chromium, `?files=memory`): place a text box, type, click away, reload, still there; a sticky in each
  colour; an ellipse given a fill by hex; change three items' colour at once and ⌘Z; Escape while editing; keyboard
  only: T, Enter, type, Escape. Axe on the board with items, light and dark. No console errors.
