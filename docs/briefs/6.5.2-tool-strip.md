## What to build

1. **One strip component** in src/ui/canvas (shared by both hosts): vertical, at the canvas's top-left corner,
   inside the canvas area, above the drawing. It takes a list of tools (id, name, key, icon, active, onSelect) from
   the host; the plan and the board each pass their own tools, in the order they have today, select and hand
   first. Every tool either host offers today as a tool or mode button is in its strip; nothing that is an action
   (zoom, export, layers, the Paper/Dark toggle) moves into it. The old row or menu of tool buttons goes away
   where the strip replaces it; say exactly what each host showed before and shows now.
2. **Look** (design/DESIGN.md): square buttons with no radius and no shadow, 1.5px rules, the strip a boxed
   surface; the active tool is an ink fill with the icon in the inverse colour (selection is an ink fill, never
   the accent); focus ring ink. The strip follows the app's theme (it is app chrome, not board content) and stays
   readable over a Paper and a Dark canvas. A canvas too short for the strip: it scrolls or wraps to a second
   column; say which you chose. Buttons at least 28 px, icons drawn at 20 px or so from the 32 px grid.
3. **Names and keys.** Each button's accessible name is its tool's name (aria-label, through t() in en and es),
   with the key exposed as `aria-keyshortcuts`. A tooltip showing "Name (Key)" appears on hover AND on keyboard
   focus (not title-only: a `title` doesn't show on focus), and never traps the pointer. The strip is one tab
   stop with arrow keys between its buttons (a toolbar, `role="toolbar"`, `aria-orientation="vertical"`), or
   plain tab stops if that is what the app's other toolbars do; be consistent with them.
4. **Icons: one SVG file per tool** in a new folder src/ui/canvas/toolIcons/ (`select.svg`, `hand.svg`, …),
   32 × 32 viewBox, 1.5 px stroke, `currentColor`, no fill unless the kit's drawing has one, round or butt caps as
   the kit's are. Where the kit already has the drawing (camera, light, cast mark, and any other tool whose kit
   icon exists: check wall, door, window, flag, diffusion, measure, north), the tool's file is that drawing (a
   copy in the folder named for the tool, so replacing one file replaces one tool; say for each tool whether it
   is the kit's or newly drawn). Draw the missing ones in the same style: select (an arrow), hand, text, note,
   sticky, shape, connector, frame/page, picture, whatever the hosts need. Loaded as the project loads its other
   SVGs (inline React components generated or imported; no network, no new dependency). A README.md in the folder
   lists each file, the tool it is for, and "kit" or "drawn here", and says how to replace one.
5. **Keys.** V selects, as now. Shift+H selects the hand tool; H still does; holding Space still pans while held.
   On both hosts. No other key changes. Keys never fire while typing in a field or a text item. The strip's
   tooltips show the keys that work today: don't invent any.
