# Brief 4.0: the service switch

For the builder (.claude/agents/builder.md). Written by the main session, Nov 9, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

The operators of the online services Storiiboard uses can stop or move what the app asks of them without anyone
installing an update (Kevin, Nov 9; docs/PHASE4_DECISIONS.md, decision 0):
- Nominatim's usage policy requires that the app's use can be switched off at its request without a software update.
- The OpenStreetMap tile policy says services may lose access at any point.
- MET Norway asks heavy users to move to a caching proxy.

So the app reads a small JSON file, kept in this repo, that can turn a service off, with a message where the service
is used, or move it to another server that is already on the code's list. It can never add a host.

Only Nominatim (the address search, 3.4) is in use today. 4.4 (MET Norway) and 4.9 (map tiles) add their services
to the same registry when they're built; build the registry so that adding one is a few lines.

## Decisions that apply

- **Where the file is (decided by default; Kevin can change it later):**
  - The repo's root, `services.json`, served from `https://raw.githubusercontent.com/mtsm-ph/storiiboard/main/services.json`.
  - It takes effect once `main` has it: `v2` merges to `main` at a release.
  - The host `raw.githubusercontent.com` is approved (Kevin, Nov 9: "the hosts for the service switch file"). Add it to `HOSTS` in src-tauri/src/net.rs with its rule in the doc comment, as Nominatim's is written.
- **When it's read:**
  - Through net.rs only.
  - At most once a day: a failed try counts, so an offline computer doesn't ask before every search.
  - Only just before an online service is used, never at startup or in the background.
- **Where it's kept:**
  - The copy last read, with the time it was fetched and the time last tried, is kept in the app's data folder (Rust side only, beside what src-tauri/src/app_data.rs keeps; not one of the files the UI may read or write there).
  - When the file can't be fetched or read, the last copy applies; with no copy, the defaults in code (every service on, on its first server).
- **What it can say, per service id:**
  - `on`, optionally with `server`, one of that service's servers in code.
  - `off`, with a `reason` code.
  - Words people see never come from the file (CLAUDE.md: every visible word through `t()`). The reason is a code mapped to translated words in en and es: `operator-request` ("Turned off at the request of the service's operator"), `maintenance` ("Turned off for now while the service is changed"), and any other code ("Turned off for now").
  - Unknown fields, unknown service ids and a `server` not on the code's list are ignored: the service stays as the defaults say, never off by mistake. A file with a `version` this app doesn't know is ignored as a whole.
- **The shape:**

  ```json
  {
    "version": 1,
    "services": {
      "nominatim": { "state": "on" }
    }
  }
  ```

  Commit this file at the repo root with Nominatim on.
- **Where a service is used and it's off:** the action says why, in place of the search, and doesn't call the network. For 4.0 that's the Locations tile's Search address (src/features/locations/AddressSearch.tsx, findPlaces.ts). Its button stays, and pressing it shows the translated reason where search errors show today.
- **Settings:**
  - A new Settings tab, "Online services", lists every online service the app may contact. Each entry gives what it's for, when it's contacted ("only when you press Search address"), its server, and its state from the switch: On; Turned off, with the reason; or "Not checked yet", before the file has been read.
  - It also says the service list itself is read from GitHub at most once a day.
  - It's built from the same registry. In a browser build (end-to-end tests) the states read "Not checked yet".
- **README:** a short section, "For service operators". It lists each service the app contacts (Nominatim: the address search, on a button press, one request a second, cached in the project; the service list on GitHub: once a day at most), the User-Agent (`Storiiboard/<version> (+https://github.com/mtsm-ph/storiiboard)`), that the operator can have the app's use turned off or moved without an update, and to reach us through GitHub issues on mtsm-ph/storiiboard.

## Files

- src-tauri/src/net.rs: add the host and its rule; reuse `get_json`.
- A new src-tauri/src/services.rs. It holds:
  - the registry: service id, servers, and which hosts each uses;
  - reading, parsing and keeping the switch file;
  - `pub(crate) async fn service_server(app, id) -> Result<String, String>`, which returns the server to use or the off reason code (as an error kind the page can tell apart, the way net.rs's error consts are told apart today: grep how src/features/locations/findPlaces.ts or src/app/addressSearch.ts turns Rust's errors into `t()` words);
  - a `#[tauri::command] services_status` for Settings.
- src-tauri/src/geocode.rs: ask `services::service_server(app, "nominatim")` before the search, and build the URL from the server it gives (today `SEARCH` is a const). Keep one request a second.
- src-tauri/src/lib.rs: register the new command.
- src/app/: a small bridge for `services_status`. Its browser fallback is "Not checked yet".
- src/features/settings/ (find the Settings window: its tabs are Project, App, Theme, Backups, Storage, Profile): the Online services tab.
- src/core/i18n/locales/en and es: every new word.
- services.json (repo root), README.md.
- docs/SBD_FORMAT.md is not touched (nothing goes in a project). Add one line to CLAUDE.md's "Files next to a project"? No: the copy is the app's, not a project's. Don't edit CLAUDE.md; the main session keeps it.

## Tests to add

- Rust (src-tauri/src/services.rs tests), all from fixtures, never GitHub:
  - parsing the shape above;
  - `off` with each reason;
  - `server` on the list (used) and off the list (ignored);
  - unknown version, unknown service, malformed JSON (each ignored as said above);
  - once a day: a fresh copy isn't fetched again, and neither is a failed try within a day;
  - the last copy applying when a fetch fails, and the defaults when there's no copy.
  - Make fetching injectable (a closure or trait) so tests never touch the network.
- net.rs: the new host is allowed, and only over HTTPS.
- Vitest: the Settings tab renders each service with each state (renderToString, as other Settings tests do), every word in en and es.
- Playwright (Chromium): Settings → Online services lists Nominatim with "Not checked yet" in a browser build. Read `e2e/` for how Settings is opened in other specs.
- Screenshots: the new tab changes the Settings screenshots (`e2e/visual.spec.ts`). Don't regenerate baselines; the main session does that and shows Kevin. Expect the four `settings-*` tests to fail locally and say so in your report.
