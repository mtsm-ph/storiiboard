# Brief 4.4: the forecast

For the builder (.claude/agents/builder.md). Written by the main session, Nov 10, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

Each location on a day's call sheet shows that day's forecast there, from MET Norway's Locationforecast
(docs/PHASE4_DECISIONS.md, decision 1; CLAUDE.md, Network rules, "Weather"). The call sheet is the Call sheet tile
(src/features/callsheets/; data from src/core/model/callsheet.ts), built in 4.1 to 4.3: read
docs/briefs/4.1-call-sheet.md, 4.2-who-and-when.md and 4.3-sun-times.md and their code first. The service switch
(4.0, src-tauri/src/services.rs, docs/briefs/4.0-service-switch.md) and the address search's cache (3.4:
src-tauri/src/geocode.rs, src/features/locations/findPlaces.ts, src/core/storage/lookups.ts, docs/SBD_FORMAT.md
"Schema v11: cached lookups") are the patterns to follow.

## Decisions that apply

- **The service:** MET Norway Locationforecast 2.0, `compact`:
  `https://api.met.no/weatherapi/locationforecast/2.0/compact?lat=<lat>&lon=<lon>`. Free for any use, paid shoots
  included; CC BY 4.0, credited "Data from MET Norway" on the sheet. Its terms: an identifying User-Agent with a way to
  reach us (net.rs's `Storiiboard/<version> (+https://github.com/mtsm-ph/storiiboard)` is that), coordinates cut to 4
  decimals (round), and never ask again for the same place before the answer's `Expires` header.
  - The host `api.met.no` is approved (Kevin, Nov 9). Add it to `HOSTS` in src-tauri/src/net.rs with its rule in the
    doc comment, as Nominatim's and raw.githubusercontent.com's are written.
  - Add it to the service switch's `REGISTRY` (src-tauri/src/services.rs) as `met-norway`, server
    `https://api.met.no/weatherapi/locationforecast/2.0`, and to src/app/servicesStatus.ts's `SERVICE_WORDS` and
    `BROWSER_SERVICES` (the Rust test `every_service_has_its_words_and_browser_entry` checks both). Its words in
    Settings → Online services: "Weather (MET Norway)", "The forecast for each location on a call sheet.", "Only when a
    call sheet is opened or refreshed, and never again for a place before the forecast says it's out of date."
  - The README's "For service operators" section gets MET Norway's line, written like Nominatim's.
- **Rust:** a new src-tauri/src/weather.rs with `#[tauri::command] weather_forecast(app, latitude, longitude)`:
  - asks `services::service_server(app, "met-norway")` first (off: the `service-off:<code>` error the page already
    turns into words, as geocode.rs does), and builds the URL from the server it gives;
  - rounds the coordinates to 4 decimals and refuses NaN or out-of-range ones;
  - fetches through net.rs. It needs the `Expires` and `Last-Modified` headers as well as the body: add a net.rs
    function that returns them with the JSON (keep every request in net.rs, HTTPS, the listed host, the generic
    User-Agent); a missing or unreadable `Expires` reads as one hour from now;
  - returns `{ expires, lastModified, fetchedAt, forecast }`, the forecast reduced in Rust to what the sheet needs
    (each timeseries entry's time, air temperature, wind speed, precipitation amount for the next hour or six,
    symbol code), so the page and the project never hold the full answer;
  - a 403 or 429 from MET Norway means stop asking: return an error the page words as "The weather service refused
    the request. Try again later." and keep no cache entry; never retry in a loop.
  - Register it in src-tauri/src/lib.rs. Rust tests from a recorded answer (a fixture file under
    src/core/net/recorded/, as geocode.rs's tests read one; write a small realistic one by hand, with a few
    timeseries entries, never fetched in a test): the reduction, the rounding, the URL, the `Expires` reading.
- **The cache:** `lookups` (src/core/storage/lookups.ts), kind `weather`, `query_key` the rounded `lat,lon`, the
  result as JSON `{ "expires", "last_modified", "forecast": [...] }`, `fetched_at` as usual. No schema change (the
  `kind` column already takes any value; update its note in SBD_FORMAT.md's "Schema v11" table and add the weather
  result's shape).
  - The page asks Rust only when the cached answer is missing, unreadable, or past its `expires`. Before then, both
    opening the sheet and pressing Refresh read the cache, and Refresh says "Up to date until 16:30" (the expiry, in the
    location's time zone, HH:MM).
  - In the browser build (`?files=memory`, end-to-end tests) the answer comes from the same recorded fixture, as
    src/core/net/recordedSearch.ts does for addresses: nothing goes online.
- **When it's asked:** only when a call sheet is opened on a day (the tile shows a day) or Refresh is pressed; once per
  location with a place on the map; never in the background, never for days not shown. A location without a place
  shows "Pick the address on the map for the forecast" (muted), as 4.3's sun times do.
- **What the sheet shows, per location, in its Sun block's neighbour "Weather":**
  - for the day in the location's time zone (4.3's zone choice: the sheet's `SheetLocation.zone`, from `zoneFor` in
    src/core/model/location.ts and `useZonesAt` in src/app/timeZone.ts; while the zone is still being found, show no
    weather either, as the Sun block does): high and low temperature, the most wind, total
    precipitation, and the conditions at the day's crew call (at noon when it has none) as words from
    the symbol code (map MET's codes to about ten translated words: clear, fair, partly cloudy, cloudy, fog, light
    rain, rain, heavy rain, sleet, snow, thunder; day/night variants of a code read the same);
  - "Forecast fetched 14:05 · Data from MET Norway" (the fetch time in the location's time zone);
  - a day beyond the forecast's last entry: "No forecast yet: it reaches as far as Thu, Nov 19"; a past day with a
    cached forecast shows it with its fetch time; a past day without one shows nothing;
  - while fetching, "Getting the forecast…"; an error shows its words in place, with Refresh to try again (which obeys
    the expiry).
- **Units (Kevin, Nov 9):** by region, °F and mph and inches in the US, °C and km/h and mm elsewhere, "the region" being
  this computer's (the same source 3.17's week start reads: src/app/weekStart.ts), with an override in Settings → App:
  "Weather units": "By this computer's region" / "Metric (°C, km/h, mm)" / "US (°F, mph, in)", kept in this
  computer's settings like the week start (src/app/preferences/AppTile.tsx and its store), never in a project. Convert
  for display only; the cache keeps MET's metric values.
- **"Changed since issued" (4.7) ignores the forecast** (decision 1): the forecast is never part of anything 4.7 will
  compare. Nothing to build now beyond keeping the forecast out of the `callsheet` record.
- **Words:** every visible word through `t()`/`tn()` in en and es; temperatures and times in JetBrains Mono.
