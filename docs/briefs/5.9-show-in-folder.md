# Brief 5.9: Show in Finder / Show in Explorer

For the builder (.claude/agents/builder.md). Written by the main session, Nov 13, 2026. Read CLAUDE.md first; its
Safety section comes before this brief. You start with no other context: everything you need is here or in the files
named.

## Goal

A picture on a board keeps a pointer to its original file (5.1b; the project stores only a copy of at most 2560 px).
Kevin, Nov 11: a person can ask to be **shown that original in its folder**: "Show in Finder" on a Mac, "Show in
Explorer" on Windows. It was left out of 5.1b because the opener rule allowed only web links and files the app wrote.
The rule now reads (CLAUDE.md, Security and privacy):

> Show in Finder / Show in Explorer (Kevin, Nov 11): the one other thing, through the opener's reveal only. It shows
> a board picture's recorded original in its folder, selected; it never opens the file, and only when the file
> exists. Rust finds the path from the picture's record in the open .sbd; the page never names one.

## Decisions that apply

- **Reveal only, never open.** Rust calls tauri-plugin-opener's reveal (`OpenerExt::reveal_item_in_dir`, version
  2.7.2 pinned in src-tauri/Cargo.toml). First confirm that method exists in the pinned version's source (in
  ~/.cargo/registry); if it doesn't, stop and report, don't add or upgrade anything. Never `open_path`, never a shell
  command of our own.
- **The page never names a path.** Two new commands in src-tauri/src/open.rs (the one place that shows or opens
  anything; update its header comment), registered in src-tauri/src/lib.rs beside `open::open_pdf`:
  - `original_shown(handle, sha256) -> bool`: whether this picture's recorded original can be shown now;
  - `reveal_original(app, handle, sha256) -> Result<(), String>`: shows it.
  Both take the open project's handle and the picture's SHA-256, exactly as `originals::picture_original` does
  (src-tauri/src/originals.rs, 5.6a), and find the path from the project's own `media` record. Reuse that file's
  lookup and every one of its refusals (make what you need `pub(crate)`; don't copy the rules): not a plain file (a
  directory, a link, a junction or other reparse point, a device, a pipe), a relative path that climbs out of the
  project's folder, `\\.\` and `\\?\` paths, a network path unless the project is on that server, and so on. The
  200 MB limit and the "is a picture by its first bytes" check are about reading; for showing, keep the picture check
  (read only the first bytes) and drop the size limit. As there, only the lookup runs under the open files' lock; the
  disk is asked after it is let go, off the main thread.
  - A file that isn't there: `original_shown` is false, and `reveal_original` refuses with a constant message (the
    file may go between the two calls). No path and no file name in any error or log (CLAUDE.md: never log personal
    data).
- **The page gets no new permission.** src-tauri/capabilities stays as it is; the test
  `the_page_has_no_opener_permission` in open.rs must pass unchanged.
- **Where it shows.** On a board, for a selected picture item, where a picture's other actions already are (read
  src/features/moodboards/: CardProperties.tsx, PictureNode.tsx, BoardView.tsx, itemMedia.ts, and docs/briefs/
  5.1b-pictures-video-links.md for how pictures were built). One picture selected: the action is there. Keyboard
  reachable, a real button or menu item with its words as its name.
  - **Only when the file exists:** the action is shown only when `original_shown` says so, asked when the picture
    becomes the selection (and again when the window regains focus), never on every draw. No recorded original, a
    missing file, a video card, several items selected, or the browser build: no action at all (not a disabled one).
  - If the reveal fails (the file went meanwhile), say so with the app's usual notice, and stop showing the action.
- **The words** (src/core/i18n/locales/en.ts and es.ts, through `t()`): by the computer the app runs on (use the
  check the code already has, e.g. `isMac()` in src/app/shell/undoShortcuts.ts, and whatever tells Windows apart):
  - Mac: "Show in Finder" / "Mostrar en Finder";
  - Windows: "Show in Explorer" / "Mostrar en el Explorador";
  - anything else (Linux dev builds): "Show in folder" / "Mostrar en la carpeta".
  - The failure: "That picture's original isn't where it was." / "El original de esa imagen ya no está donde
    estaba."
- **Not an edit.** Nothing is written to the project: no op, nothing in History, nothing for ⌘Z.
- **Page side** in src/app/opener.ts, beside `openLink` and `openPdf` (update its header comment): `originalShown`
  and `revealOriginal`. In a browser build both do nothing and say no. For the end-to-end tests (a dev build opened
  with `?files=memory`, which has no Rust), follow the way 5.6a's originals are stood in for there
  (src/features/export/deckPictures.ts and its e2e/deckExport.spec.ts) so a test can say "this picture's original
  exists" and see that the reveal was asked for with that picture's hash; dev only, never in a release build.

## Tests to add

- Rust (open.rs): a real file in a temp project folder is found and passes; a missing file is `false` and refused; a
  directory, a link to a file (skip where the test can't make one), a path climbing out of the project's folder, a
  `\\?\` path and a file that isn't a picture are all refused; a picture the project has no record of is refused.
  The reveal itself can't run in a test: put everything up to the plugin call in a function the tests call.
- Vitest: the label for Mac, Windows and other, in English and Spanish; the rule for when the action shows (one
  picture with an original that exists: yes; none recorded, missing, a video card, two items selected, browser
  build: no).
- End to end (Chromium): a picture whose original "exists" shows the action, reachable and pressed from the
  keyboard, and the reveal is asked for with that picture's hash; a picture without one shows no such action; a
  failed reveal shows the notice and the action goes. The spec's console-error check stays as it is.
